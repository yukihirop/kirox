# Kirox CLI - Product Overview

## Product Overview

Kirox CLIは、リモートGitHubリポジトリからKiro仕様書とステアリングファイルを取得するnpxコマンドラインツールです。開発者がプロジェクト間でSpec-Driven Developmentの成果物を簡単に共有・再利用できるようにすることで、開発の一貫性と効率性を向上させます。

## Core Features

- **リモートリポジトリからのファイル取得**: 指定したGitHubリポジトリから`.kiro/specs/<project>`および`.kiro/steering/`配下の全ファイルを自動取得
- **npx即時実行**: グローバルインストール不要、`npx kirox`コマンドで即座に実行可能
- **上書き保護**: 既存ローカルファイルの意図しない上書きを防ぐ確認プロンプト機能
- **進捗可視化**: リアルタイムでファイル取得状況を表示し、完了時には成功・失敗数をサマリー表示
- **エラーハンドリング**: GitHub API制約（レート制限、ファイルサイズ制限）への適切な対応と明確なエラーメッセージ
- **柔軟な設定**: 設定ファイル（.kiroxrc.json）による動作カスタマイズと複数オプション（--force、--dry-run、--verbose）のサポート

## Target Use Case

### Primary Use Case: プロジェクト間でのSpec成果物共有

チーム開発や複数プロジェクトで同じSpec-Driven Developmentの手法を使用する場合、以下のシナリオで活用できます：

1. **新規プロジェクトへのテンプレート適用**
   - 既存プロジェクトの成功した仕様書パターンを新規プロジェクトにコピー
   - `npx kirox team-repo/template-project -p api-spec`で即座に取得

2. **共通ステアリング情報の同期**
   - チーム全体で共有する開発ガイドライン（tech.md、structure.md等）を一元管理
   - リポジトリ更新後、各プロジェクトで`npx kirox`実行により最新版を取得

3. **仕様書のバージョン管理とレビュー**
   - レビュー済みの仕様書を中央リポジトリで管理
   - 開発者は承認された仕様のみをローカルに取得して実装

4. **クロスプロジェクトのベストプラクティス共有**
   - 成功したプロジェクトの仕様書をリファレンスとして他プロジェクトに展開
   - ドメイン知識や設計パターンの再利用促進

### Secondary Use Case: 個人開発者のワークフロー効率化

- 自分の過去プロジェクトから仕様書テンプレートを再利用
- よく使うステアリング設定を個人リポジトリで管理し、新プロジェクトに即座に適用

## Key Value Proposition

### 1. 開発の一貫性とスピード向上

- **仕様書の手動コピーを自動化**: GitHub上の成果物をコマンド1つで取得、コピー＆ペーストの手間を削減
- **最新版の自動取得**: npxにより常に最新バージョンのツールを実行、バージョン管理不要
- **設定の再利用**: .kiroxrc.jsonで頻繁に使う設定を保存、毎回のオプション指定不要

### 2. 安全性と信頼性

- **上書き保護**: 既存ファイルを誤って上書きするリスクを確認プロンプトで防止
- **部分的な失敗の許容**: 一部ファイル取得失敗時も処理を継続し、成功したファイルは確実に取得
- **明確なエラーメッセージ**: 問題発生時に具体的な原因と解決策を提示

### 3. 優れた開発者体験（DX）

- **インストール不要**: npxによる即時実行、環境構築の手間なし
- **リアルタイム進捗表示**: 処理状況を視覚的に把握、完了までの見通しを提供
- **柔軟なオプション**: --dry-runで事前確認、--verboseで詳細ログ、--configでカスタム設定
- **GitHub API制約への自動対応**: レート制限やファイルサイズ制限を意識せずに利用可能

### 4. チーム開発の効率化

- **仕様書の標準化促進**: チーム全体で同じテンプレートや構造を共有
- **知識の民主化**: 経験豊富なメンバーの仕様書パターンを全員が活用可能
- **レビュープロセスの簡素化**: 承認済み仕様のみをリポジトリで管理し、配布を自動化
