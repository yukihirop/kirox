# Implementation Plan

## Overview

本実装計画は、GitHub Tree APIを使用したリポジトリ横断的なプロジェクト検出機能と、検索可能なプロジェクト選択UIを統合します。既存の`kirox-suggest-project`機能を拡張し、サブディレクトリ入力ステップを条件付きでスキップする新しいワークフローを追加します。

## Tasks

- [x] 1. GitHub Tree APIクライアントとレスポンスパーサーの実装
- [x] 1.1 Tree SHA取得機能の実装
  - リポジトリのデフォルトブランチ情報を取得する機能を実装
  - 指定されたブランチのTree SHAを取得する機能を実装
  - ブランチ指定なしの場合、デフォルトブランチのTree SHAを取得
  - エラーハンドリング（404: ブランチ未検出、401/403: 認証エラー）
  - _Requirements: 1.4, 1.5_

- [x] 1.2 Tree APIレスポンスのフィルタリングと解析機能の実装
  - Tree APIレスポンスから`.kiro/specs/`を含むパスのみを抽出
  - 正規表現パターン`/^(?:(.+?)\/)?\.kiro\/specs\/([^/]+)$/`を使用してプロジェクト名とサブディレクトリパスを識別
  - ディレクトリタイプ（`type === 'tree'`）のみをフィルタリング
  - 不要なファイルエントリを早期にスキップして効率化
  - _Requirements: 1.2, 1.3, 8.1, 8.2_

- [x] 1.3 ProjectLocation型の構築機能の実装
  - プロジェクト名、サブディレクトリパス、表示名を含むProjectLocation型を生成
  - ルートディレクトリのプロジェクトは`displayName`をプロジェクト名のみに設定
  - サブディレクトリのプロジェクトは`displayName`を「サブディレクトリパス/プロジェクト名」形式に設定
  - 重複プロジェクト名を検出し、サブディレクトリで区別
  - _Requirements: 2.1, 2.2, 2.3, 8.3_

- [x] 2. TreeBasedProjectScannerサービスの実装 (All tasks completed: 2.1-2.5)
- [x] 2.1 コアスキャン機能の実装
  - GitHub Tree APIを呼び出してリポジトリ全体を再帰的に検索（`recursive=1`）
  - Tree SHAを使用してTree APIエンドポイントを呼び出し
  - レスポンスからProjectLocationリストを生成
  - `truncated`フラグを検出し、TreeScanResultに伝播
  - _Requirements: 1.1, 1.6_

- [x] 2.2 プロジェクトのアルファベット順ソート機能の実装
  - サブディレクトリパスをアルファベット順にソート
  - 同じサブディレクトリ内のプロジェクトもアルファベット順にソート
  - _Requirements: 2.4_

- [x] 2.3 エラーハンドリングとフォールバック機能の実装
  - 404エラー: 「リポジトリまたはブランチが見つかりません」メッセージと共にフォールバック
  - 409エラー（空リポジトリ）: 「リポジトリが空です」メッセージと共にフォールバック

  - その他のエラー: 「Tree API呼び出しに失敗しました」メッセージと共にフォールバック

## Implementation Notes

### Technology Stack
- **既存依存のみ使用**: 新しい外部ライブラリは追加しない
- **@inquirer/prompts**: `search`プロンプトを新規使用（既存パッケージに含まれる）
- **Octokit**: GitHub Tree APIエンドポイントを新規使用

### File Organization
- **新規ファイル**: `src/cli/tree-based-project-scanner.ts`、`src/cli/searchable-project-prompt.ts`
- **拡張ファイル**: `src/cli/interactive-prompt.ts`（promptMissingArguments関数）
- **テストファイル**: `tests/unit/cli/tree-based-project-scanner.test.ts`、`tests/unit/cli/searchable-project-prompt.test.ts`、`tests/integration/tree-api-project-scan.test.ts`、`tests/e2e/tree-based-project-selection.test.ts`

### Key Design Decisions
1. **Tree APIベースの横断検索**: 1回のAPI呼び出しでリポジトリ全体を検索
2. **検索可能なプロジェクト選択UI**: `@inquirer/prompts`の`search`プロンプトを使用
3. **複数選択時の同一サブディレクトリ制約**: 動的フィルタリングで意図しない組み合わせを防止

### Testing Strategy
- **単体テスト**: 各コンポーネントのコアロジックを個別にテスト
- **統合テスト**: Tree API → プロジェクト一覧取得の完全フローをテスト
- **E2Eテスト**: インタラクティブモードの完全なユーザーフローをテスト
- **後方互換性**: 既存機能が壊れていないことを確認
