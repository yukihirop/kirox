# Implementation Plan

- [ ] 1. GitHub APIブランチ取得機能の実装
- [x] 1.1 デフォルトブランチ取得機能の実装
  - リポジトリ情報取得APIを呼び出し、デフォルトブランチ名を取得する機能を実装
  - API呼び出し失敗時に適切なエラーをスローし、エラーメッセージに詳細情報を含める
  - リポジトリが見つからない場合の404エラーハンドリングを実装
  - 認証エラー（401/403）の適切なハンドリングを実装
  - _Requirements: 2.1, 2.3, 2.4_

- [x] 1.2 ブランチ一覧取得機能の実装
  - GitHub APIを使用してリポジトリの全ブランチを取得する機能を実装
  - ページネーション処理を実装し、100件以上のブランチを全て取得できるようにする
  - 取得したブランチ名を配列として返す機能を実装
  - API呼び出し失敗時の適切なエラーハンドリングを実装
  - 認証トークン（GITHUB_TOKEN）を使用したプライベートリポジトリアクセスをサポート
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 1.3 GitHub API機能の単体テスト作成
  - デフォルトブランチ取得の正常系テストを作成（デフォルトブランチ名を正しく返すことを検証）
  - デフォルトブランチ取得の異常系テスト（404エラー、認証エラー）を作成
  - ブランチ一覧取得の正常系テストを作成（ブランチ名配列を正しく返すことを検証）
  - ブランチ一覧取得のページネーションテストを作成（100件以上のブランチ取得を検証）
  - ブランチ一覧取得の異常系テスト（404エラー、認証エラー、空配列）を作成
  - Octokitクライアントをモックし、外部API依存を排除したテストを実装
  - _Requirements: 12.1, 12.2_

- [ ] 2. ブランチ選択プロンプトUIの実装
- [x] 2.1 promptBranch関数の実装
  - searchable-checkboxを使用したブランチ選択UIを実装
  - ブランチ一覧とデフォルトブランチを受け取り、UIに表示する機能を実装
  - デフォルトブランチに「(default)」ラベルを付けて表示する機能を実装
  - ブランチ一覧をソート（デフォルトブランチを最上位、その他をアルファベット順）する機能を実装
  - ユーザーが選択したブランチ名を返す機能、または0件選択時にundefinedを返す機能を実装
  - _Requirements: 3.1, 3.5, 3.6, 3.7_

- [x] 2.2 ブランチ選択バリデーションの実装
  - searchable-checkboxのバリデーション機能を使用し、単一ブランチ選択のみを許可する
  - 複数ブランチ選択時に「Please select only one branch」エラーメッセージを表示する
  - 0件選択時にバリデーションを通過させ、undefinedを返す機能を実装
  - _Requirements: 4.1, 4.2_

- [x] 2.3 promptBranch関数の単体テスト作成
  - 正常系テスト：ユーザーがブランチを選択した場合のテストを作成
  - デフォルトラベルテスト：デフォルトブランチに「(default)」ラベルが付くことを検証
  - ソート順テスト：デフォルトブランチが最上位、その他がアルファベット順であることを検証
  - 0件選択テスト：0件選択時にundefinedを返すことを検証
  - 複数選択テスト：複数選択時にバリデーションエラーが表示されることを検証
  - UIインタラクションをモックし、ユーザー操作をシミュレートしたテストを実装
  - _Requirements: 12.3_

- [ ] 3. 対話モードフローへの統合
- [x] 3.1 promptMissingArguments関数へのブランチ選択ロジック追加
  - リポジトリ入力後、リポジトリ文字列に「#branch」が含まれるかチェックする機能を実装
  - 「#branch」が含まれる場合、ブランチ選択プロンプトをスキップする機能を実装
  - 「#branch」が含まれない場合、ブランチ選択プロンプトを表示する機能を実装
  - ブランチ選択完了後、選択されたブランチをリポジトリ文字列に「#branch」形式で追加する機能を実装
  - 0件選択時にデフォルトブランチをリポジトリ文字列に追加する機能を実装
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_

- [x] 3.2 デフォルトブランチ取得とエラーハンドリング統合
  - デフォルトブランチ取得API呼び出しを実装し、失敗時にログを記録して処理を継続する
  - デフォルトブランチ取得成功時にverboseモードでログを記録する機能を実装
  - デフォルトブランチ取得失敗時にwarningログを記録し、undefinedで処理を継続する機能を実装
  - _Requirements: 7.2, 11.3_

- [ ] 3.3 ブランチ一覧取得とエラーハンドリング統合
  - ブランチ一覧取得API呼び出しを実装し、失敗時にエラーメッセージを表示して処理を継続する
  - ローディングメッセージ「Fetching branches...」を表示する機能を実装
  - ブランチ一覧取得成功時にverboseモードでブランチ数をログに記録する機能を実装
  - ブランチ一覧が0件の場合に「No branches found in repository」エラーメッセージを表示し、プロンプトをスキップする機能を実装
  - API失敗時にデフォルトブランチへフォールバックする機能を実装
  - レート制限エラー、ネットワークエラーの適切なエラーメッセージ表示を実装
  - _Requirements: 4.4, 7.1, 7.3, 7.4, 9.5, 11.1, 11.2_

- [ ] 3.4 ブランチ選択完了後のログ記録実装
  - ブランチ選択完了時にverboseモードで選択されたブランチ名をログに記録する機能を実装
  - 0件選択時（デフォルトブランチ使用）のログ記録を実装
  - Ctrl+C中断時のログ記録を実装
  - _Requirements: 11.4, 11.5_

- [ ] 3.5 promptMissingArguments統合ロジックの統合テスト作成
  - ブランチ選択フロー全体のテスト：リポジトリ入力→デフォルトブランチ取得→ブランチ一覧取得→ブランチ選択→リポジトリ文字列更新
  - スキップロジックテスト：「#branch」を含むリポジトリ入力時にブランチ選択がスキップされることを検証
  - フォールバックテスト：API失敗時にデフォルトブランチにフォールバックすることを検証
  - Tree API連携テスト：ブランチが適用されたリポジトリ文字列でTree API検索が実行されることを検証
  - デフォルトブランチ取得失敗時もブランチ一覧取得が実行されることを検証
  - _Requirements: 10.1, 統合テストケース_

- [ ] 4. リポジトリ入力プロンプトメッセージの更新
- [ ] 4.1 promptRepository関数のメッセージ変更
  - リポジトリ入力プロンプトメッセージはそのまま維持（「Enter GitHub repository (owner/repo or owner/repo#branch)」）
  - owner/repo#branch形式の入力は既存機能として引き続きサポート
  - _Requirements: 6.1, 6.2_

- [ ] 5. 非対話モード動作保証のテスト作成
- [ ] 5.1 非対話モードでの動作テスト作成
  - リポジトリが「owner/repo#branch」形式で引数指定されている場合、ブランチ選択プロンプトが表示されないことを検証
  - リポジトリが「owner/repo」形式で引数指定されている場合、ブランチ選択プロンプトが表示されないことを検証
  - TTY環境でない場合、ブランチ選択プロンプトが表示されないことを検証
  - 「--update」または「--check-updates」オプション指定時、ブランチ選択プロンプトが表示されないことを検証
  - _Requirements: 8.1, 8.2, 8.3, 8.4_

- [ ] 6. E2Eテストの作成
- [ ] 6.1 対話モード完全フローのE2Eテスト作成
  - 正常フロー：リポジトリ入力→ブランチ選択→プロジェクト選択→確認→ファイル取得の完全フローを検証
  - ブランチ指定済みフロー：「owner/repo#branch」形式での入力時にブランチ選択がスキップされることを検証
  - Ctrl+C中断フロー：ブランチ選択中のCtrl+Cで適切に終了（exitCode=130）することを検証
  - 0件選択フロー：0件選択時にデフォルトブランチで処理が継続されることを検証
  - _Requirements: 対話モード完全フローの検証_

- [ ] 6.2 既存機能との統合互換性E2Eテスト作成
  - Tree API検索連携テスト：ブランチが適用されたリポジトリ文字列でTree API検索が実行されることを検証
  - プロジェクト選択連携テスト：選択されたブランチのプロジェクト一覧が表示されることを検証
  - サブディレクトリ連携テスト：選択されたブランチのサブディレクトリが取得されることを検証
  - 確認プロンプト連携テスト：選択されたブランチ情報が確認サマリーに含まれることを検証
  - _Requirements: 10.1, 10.2, 10.3, 10.4_

- [ ] 7. パフォーマンステストの作成
- [ ] 7.1 ブランチ取得パフォーマンステスト作成
  - ブランチ一覧取得が3秒以内に完了することを検証（通常のネットワーク環境下）
  - 100個以上のブランチに対してリアルタイム検索フィルタリングが1秒以内に完了することを検証
  - 検索テキスト入力時のフィルタリング結果が100ms以内に表示されることを検証
  - _Requirements: 9.1, 9.2, 9.3_
